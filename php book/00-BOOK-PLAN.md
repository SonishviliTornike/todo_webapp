# PHP: ნულიდან სენიორამდე
### წიგნის გეგმა და სამუშაო წესები

---

## 0. რა არის ეს წიგნი

ერთი მთლიანი, თანმიმდევრული წიგნი, რომელიც იწყება ნულიდან — იმ დაშვებით, რომ PHP-ს საერთოდ არ იცნობ — და მთავრდება იმ ცოდნით, რომელსაც სენიორ დეველოპერისგან მოელიან.

**რას ნიშნავს აქ "ნულიდან":** პირველი ნაწილი არ გამოტოვებს არაფერს, მაგრამ არც გაწელავს. ცვლადებზე და ციკლებზე დახარჯული იქნება ის დრო, რაც საკმარისია — და არა უფრო მეტი. სამაგიეროდ, უკვე პირველივე თავში საუბარია იმაზე, თუ *რატომ* არის ეს ასე და სად ჩავარდება ის, ვინც ამას ზედაპირულად ისწავლის.

**რა განასხვავებს მას სახელმძღვანელოსგან:** სახელმძღვანელო გასწავლის, *რა შეიძლება გააკეთო*. ეს წიგნი გასწავლის, **რა უნდა გააკეთო, რა არ უნდა გააკეთო, და საიდან იცი განსხვავება.** ყოველ თემაზე მოცემულია:
- როდის არის ეს ინსტრუმენტი სწორი არჩევანი
- როდის არის ის არასწორი არჩევანი (ეს უფრო მნიშვნელოვანია)
- რა შეცდომას უშვებენ ყველაზე ხშირად
- როგორ გამოიყურება ეს კოდი პროდაქშენში, სამწლიანი ისტორიის შემდეგ

## 1. სამუშაო წესები

**რიტმი:** 30-60 წუთი დღეში. ერთი თავი ჩვეულებრივ 2-4 სესიაა.

**ყოველი თავის სტრუქტურა:**

| სექცია | დანიშნულება |
|---|---|
| **პრობლემა** | რა პრობლემა არსებობდა, სანამ ეს ცნება გაჩნდებოდა. ცნება, რომლის პრობლემას ვერ ხედავ, არ არის ნასწავლი |
| **თეორია** | მექანიკა ბოლომდე — რა ხდება სინამდვილეში, არა ანალოგიები |
| **პრაქტიკა** | სრული, მუშა კოდი |
| **როდის კი და როდის არა** | არჩევანის კრიტერიუმები, ტრეიდოფებით |
| **ანტიპატერნები** | ცხრილი: შეცდომა → რატომ არის შეცდომა → რა მოხდება |
| **პრინციპებთან კავშირი** | DRY, KISS, YAGNI, SOLID, PSR — არა ლოზუნგად, არამედ ამ თემაზე მიბმულად |
| **სენიორული ხედვა** | გადაწყვეტილების ჩარჩო, რომელიც შემდეგ ჯერზეც იმუშავებს |
| **პროექტი** | ნაბიჯი მაღაზიის აშენებაში |
| **კითხვები** | 20-25 კითხვა, პასუხების გარეშე |

**კითხვები:** პასუხები წიგნში არ არის და არ იქნება. პასუხობ ჩატში, მე ვასწორებ უკომპრომისოდ — ნაწილობრივი ქულა არ არსებობს. ტიპები: `[ცოდნა]` `[რატომ]` `[ხაფანგი]` `[code review]` `[არქიტექტურა]` `[უსაფრთხოება]`.

**თავის დახურვის ზღვარი:** ≥22/25 დოკუმენტაციის გარეშე.

## 2. გამჭოლი პროექტი — ონლაინ მაღაზია

წიგნი აშენებს ერთ სისტემას თავიდან ბოლომდე: **ელექტრონული კომერციის მაღაზიას**, სუფთა PHP-ზე, ფრეიმვორკის გარეშე.

რატომ მაღაზია: ის შეიცავს ყველა რთულ პრობლემას, რომელიც სენიორული აზროვნების საზომია — **ფული** (შეცდომა = ფინანსური ინციდენტი), **მარაგი** (ბოლო ერთი ცალი ეკუთვნის ერთს, არა ორს), **გარე სისტემები, რომლებიც ცრუობენ** (გადახდის სერვისი, კურიერი), **მასშტაბი** (250 000 პროდუქტი), **უფლებები** (მომხმარებელი ვერ ხედავს სხვის შეკვეთას).

პროექტი იზრდება წიგნთან ერთად: I ნაწილში ეს არის ერთი სკრიპტი, VII ნაწილში — ტესტებით დაფარული, დაცული, პროდაქშენში გაშვებადი აპლიკაცია.

## 3. სრული სარჩევი

### ნაწილი I — ენა (სწრაფად, მაგრამ სწორად) · 4 თავი

**1. PHP, ტიპები, გამოსახულებები** — რა არის PHP და როგორ სრულდება; ცვლადები; ყველა ტიპი; ტიპთა კონვერსია და შედარებები; ოპერატორები და პრიორიტეტი; სტრიქონები, ინტერპოლაცია, heredoc; კონსტანტები; `strict_types`; ფულის წარმოდგენის პრობლემა.

**2. მართვის ნაკადი და ფუნქციები** — `if`/`match`/`switch`; ციკლები; ფუნქციები; პარამეტრები, ნაგულისხმევი მნიშვნელობები, ტიპები; დაბრუნების ტიპები; არეალი; closure-ები და `fn`; ვარიადიკები; დასახელებული არგუმენტები; რეკურსია; სუფთა ფუნქციები და გვერდითი ეფექტები.

**3. მასივები, სტრიქონები, მონაცემთა ფორმები** — მასივის ბუნება; სია vs რუკა; `map`/`filter`/`reduce`; სორტირება; მრავალგანზომილებიანი მონაცემები; სტრიქონების დამუშავება; მრავალბაიტიანობა და UTF-8; JSON; თარიღები და დროის ზონები.

**4. შეყვანა, გამონატანი, ფაილები** — `include`/`require`; სუპერგლობალები; HTTP-ს საფუძვლები; ფორმები; ფაილური სისტემა; CLI; **პირველი უსაფრთხოების გაკვეთილი: არასოდეს ენდო შეყვანას**.

### ნაწილი II — ობიექტზე ორიენტირებული PHP · 7 თავი

**5. კლასები და ობიექტები** — კლასი vs ობიექტი; თვისებები, მეთოდები, ხილვადობა; კონსტრუქტორი და promotion; `$this`; იდენტობა vs ტოლობა; `clone`; `readonly`; რატომ არის ინკაფსულაცია ინსტრუმენტი და არა წესი.

**6. მემკვიდრეობა, აბსტრაქცია, ინტერფეისები** — `extends`; მეთოდის გადაფარვა; `abstract`; `interface`; **კონტრაქტი vs იდენტობა**; `final`-ის ფილოსოფია; fragile base class; კომპოზიცია მემკვიდრეობის ნაცვლად — გაზომვადი გადაწყვეტილება.

**7. Traits, სტატიკა, კონსტანტები** — trait-ები და კონფლიქტების მოგვარება; სტატიკური წევრები და მათი ფასი; late static binding; კლასის კონსტანტები; როდის არის სტატიკა ლეგიტიმური და როდის დამალული გლობალი.

**8. მაგიური მეთოდები, ინტერფეისები SPL-იდან, იტერაცია** — `__get`/`__set`/`__call` და რატომ არის ეს დიზაინის სუნი; `__invoke`, `__toString`; `ArrayAccess`, `Countable`, `IteratorAggregate`; გენერატორები; Reflection და ატრიბუტები.

**9. შეცდომები და გამონაკლისები** — `Throwable`; `Error` vs `Exception`; საკუთარი იერარქიის დიზაინი; `try/catch/finally`-ის ზუსტი სემანტიკა; როდის გამონაკლისი და როდის დაბრუნებული მნიშვნელობა; გლობალური დამუშავება; რას ხედავს მომხმარებელი და რას ლოგი.

**10. Enum, Value Object, უცვლელობა** — enum-ები და სტატუსების მოდელირება; Value Object (`Money`, `Sku`, `Email`); ტოლობა; უცვლელობა როგორც უსაფრთხოების ინსტრუმენტი; **პრიმიტიული აკვიატების** მოშორება.

**11. Namespace, ავტოჩატვირთვა, Composer** — namespace-ების მექანიკა; `use` და მისი რეალური მნიშვნელობა; PSR-4; Composer-ის autoloader შიგნიდან; დამოკიდებულებების მართვა, ვერსირება, `composer.lock`; პაკეტის არჩევის კრიტერიუმები.

### ნაწილი III — ძრავი · 4 თავი

**12. როგორ სრულდება მოთხოვნა** — MINIT/RINIT/RSHUTDOWN; დასრულების ზუსტი რიგი; დესტრუქტორები vs shutdown ფუნქციები; SAPI და PHP-FPM; worker-ების ბლოკირება; კლიენტის გათიშვა; **რატომ იკარგება შეკვეთები**.

**13. ტიპების სისტემა სიღრმეში** — ტიპთა ჟონგლირება ბოლომდე; `strict_types`-ის რეალური არეალი; union/intersection/`never`; ვარიანტულობა და LSP მექანიკურად; ტიპები როგორც დოკუმენტაცია.

**14. მეხსიერება და შესრულება** — copy-on-write; refcount და GC; მიმართვები (`&`); მასივის შიდა აღნაგობა; გენერატორები 250 000 ჩანაწერზე; მეხსიერების ლიმიტები.

**15. OPcache და გაზომვა** — კომპილაციის ჯაჭვი; opcode-ები; OPcache და preloading; JIT-ის რეალობა; პროფაილინგის საფუძვლები; **რატომ არის ინტუიცია შესრულებაზე თითქმის ყოველთვის მცდარი**.

### ნაწილი IV — არქიტექტურა · 8 თავი

**16. სუფთა კოდი და პრინციპები** — სახელდება; ფუნქციის ზომა; კომენტარები (და რატომ არის მათი უმეტესობა მარცხის ნიშანი); **DRY — რეალური განმარტება** (ცოდნის ერთი წყარო, არა ტექსტის არადუბლირება); KISS; YAGNI; ადრეული აბსტრაქციის ფასი.

**17. SOLID** — ხუთივე პრინციპი ცალ-ცალკე, სწორი და არასწორი მაგალითით; და ცალკე სექცია: **როდის არ უნდა გამოიყენო SOLID**.

**18. დამოკიდებულებები და DI კონტეინერი** — dependency injection ხელით; რატომ ვერ მასშტაბირდება; კონტეინერი ნულიდან, autowiring რეფლექსიით; service locator როგორც ანტიპატერნი; composition root; სერვისების სიცოცხლის ციკლი.

**19. ფენები და საზღვრები** — controller / service / repository / domain; entity vs DTO vs model; რას აკეთებს რეპოზიტორი და რას ტყუის; ბიზნეს-ლოგიკის ადგილი; anemic model-ის დებატი; შემოსაზღვრული კონტექსტები.

**20. დიზაინის პატერნები I — შემქმნელი და სტრუქტურული** — Factory, Builder, Adapter, Decorator, Proxy, Null Object; თითოეული რეალურ ამოცანაზე; ანტიკოროზიული ფენა.

**21. დიზაინის პატერნები II — ქცევითი** — Strategy, Observer/Events, Command, Template Method, State, Chain of Responsibility; **პატერნებით გადატვირთვის საშიშროება**.

**22. HTTP და აპლიკაციის კარიბჭე** — HTTP როგორც კონტრაქტი; იდემპოტენტობა; Request/Response ობიექტები; front controller; როუტერი ნულიდან; middleware pipeline; PSR-7/15.

**23. შაბლონები და გამონატანი** — ხედის ფენა; escape-ი კონტექსტის მიხედვით; შაბლონების ორგანიზება; რატომ არ არის ლოგიკა შაბლონში; კომპონენტები და განმეორებადობა.

### ნაწილი V — მონაცემები · 5 თავი

**24. SQL და სქემის დიზაინი** — რელაციური მოდელი; ნორმალიზაცია და როდის დაარღვიო; ტიპების არჩევა; გასაღებები და კავშირები; `JOIN`-ები; აგრეგაცია; მაღაზიის სქემა ბოლომდე.

**25. PDO** — კავშირი; **prepared statements პროტოკოლის დონეზე**; emulation; fetch რეჟიმები; ტრანზაქციები; შეცდომების დამუშავება; რას აკეთებს ORM და რას იხდი მისთვის.

**26. რეპოზიტორიები და მიგრაციები** — ჰიდრაცია ობიექტებში; იდენტობის რუკა; მიგრაციები და სქემის ვერსირება გუნდში; seed-ები; ტესტური მონაცემები.

**27. შესრულება მონაცემებზე** — ინდექსები და `EXPLAIN`; **N+1**; პაგინაცია 250 000 ჩანაწერზე (offset vs keyset); ტრანზაქციები და იზოლაცია; **კონკურენტულობა: ბოლო ერთი ცალის პრობლემა**; deadlock-ები.

**28. კეშირება** — ფენები; რა უნდა დაიკეშოს და რა არა; ინვალიდაცია; stampede; იდემპოტენტობა; კეშირება როგორც სირთულის წყარო.

### ნაწილი VI — უსაფრთხოება · 5 თავი

**29. საფრთხის მოდელი** — ნდობის საზღვრები; STRIDE; defense in depth; least privilege; fail closed; მაღაზიის საფრთხის რუკა.

**30. Injection და XSS** — SQLi ყველა ფორმით (მათ შორის second-order); რას ვერ აპარამეტრებ; XSS კონტექსტების მიხედვით; command injection, path traversal, header injection; შაბლონების ავტოescape და მისი ხვრელები.

**31. ავთენტიფიკაცია** — სესიის მექანიკა; fixation და hijacking; ქუქის ფლაგები; პაროლების ჰეშირება და cost; rate limiting; მომხმარებელთა ჩამოთვლა; remember-me; MFA; OAuth/OIDC/JWT-ის რეალური სემანტიკა.

**32. ავტორიზაცია** — RBAC vs ABAC; **IDOR — ყველაზე ხშირი და ყველაზე ძვირი ხვრელი**; ცენტრალიზებული გადაწყვეტილება; ავტორიზაცია დომენში vs კონტროლერში; აუდიტის ჟურნალი.

**33. დანარჩენი ზედაპირი** — CSRF; SameSite; CORS; CSP და header-ები; ფაილების ატვირთვა; `unserialize()` და POP ჯაჭვები; SSRF; საიდუმლოებების მართვა; დამოკიდებულებების უსაფრთხოება.

### ნაწილი VII — პროფესიონალიზმი · 7 თავი

**34. ტესტირება** — რას ტესტავ და რას არა; unit/integration/e2e; test doubles-ის ოთხი ტიპი; ტესტირებადობა როგორც დიზაინის უკუკავშირი; ტესტები ბაზასთან; TDD რეალობაში.

**35. ხარისხის ინსტრუმენტები** — PHPStan დონეები; ტიპიზაცია docblock-ებით; CS Fixer; CI კარიბჭეები; მეტრიკები, რომლებსაც აზრი აქვს.

**36. Legacy და რეფაქტორინგი** — როგორ კითხულობ უცხო კოდს; მახასიათებლების ტესტი; სტრანგულაციის ნიმუში; ტექნიკური ვალი როგორც ფინანსური ცნება; როგორ არ გადაწერო ყველაფერი ნულიდან.

**37. ლოგირება და დაკვირვებადობა** — რას ლოგავ და რას არასოდეს (PII, ბარათები, ტოკენები); სტრუქტურირებული ლოგები; კორელაციის ID; მეტრიკები; ინციდენტის დიაგნოსტიკა.

**38. ფონური სამუშაო** — რიგები; worker-ები; იდემპოტენტობა; ხელახალი ცდები და backoff; მკვდარი წერილების რიგი; cron vs რიგი; **რა არასოდეს კეთდება HTTP მოთხოვნაში**.

**39. API დიზაინი** — REST-ის რეალობა; რესურსები; სტატუსები; ვერსირება; შეცდომების ფორმატი; პაგინაცია; rate limiting; დოკუმენტაცია; webhook-ები.

**40. გაშვება პროდაქშენში** — 12-factor; კონფიგურაცია გარემოდან; Docker dev vs prod; მიგრაციები დეპლოიში; zero-downtime; rollback; მონიტორინგი.

**41. სენიორული აზროვნება** — ტრეიდოფები როგორც ერთადერთი რეალობა; გადაწყვეტილებების დოკუმენტირება (ADR); code review — როგორ აკეთებ და როგორ იღებ; შეფასება და ვადები; როდის ამბობ "არა"; როგორ ეუბნები ბიზნესს ტექნიკურ სიმართლეს.
